# Séance 22 — 2026-08-02 — SQL (2) : SELECT

## Objectif de la séance
Interroger les données : `SELECT`, `WHERE`, `LIKE`.

## Révision éclair
- CREATE (structure, une fois) vs INSERT (données, répétable) : a redonné CREATE + « une fois » ; INSERT nommé en complément.
- Guillemets simples pour le texte : **juste**.

## Ce qui a été vu
- `SELECT * FROM table` (toutes colonnes) ; `SELECT col1, col2 FROM table`.
- `WHERE condition` pour filtrer ; comparaison avec un seul `=` ; texte en guillemets simples.
- `LIKE '192.168.1.%'` : filtrage par motif, **`%` = joker** (« n'importe quels caractères »).

## Exercice fait — requêtes sur `machines`
1. `SELECT * FROM machines;` → 3 lignes ✓
2. `SELECT nom FROM machines;` → 3 noms ✓
3. `SELECT * FROM machines WHERE nom = 'Imprimante du bureau';` → 1 ligne ✓
4. `SELECT * FROM machines WHERE ip LIKE '192.168.1.%';` → **seulement Server-Web** (192.168.10.0 exclue) ✓

## Difficultés / observations
- **Les 4 requêtes justes du 1er coup**, y compris le `LIKE` + `%` (le point + joker = filtre réseau précis).
- **Gros déclic** montré : son outil d'audit Python complet = **une seule ligne SELECT**. Illustration parfaite de la puissance du SQL.
- Réactivation SQL très fluide, rythme rapide.

## Concepts — bilan
- `SELECT` / `WHERE` / `LIKE %` → **vu, réussi** (réactivation solide). À recroiser.

## Prochaine étape prévue
Compléter le **CRUD** : `ORDER BY` (trier), puis **`UPDATE`** (modifier des lignes) et **`DELETE`** (supprimer) — avec la prudence du `WHERE` (sans WHERE, ça touche TOUTE la table !). Ensuite : agrégations (`COUNT`, `GROUP BY`), jointures, puis relier SQL à Python (`sqlite3`). Drills : `LIKE %`, INSERT vs CREATE.
