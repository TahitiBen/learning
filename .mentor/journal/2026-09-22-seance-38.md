## Ce qui a été vu
- **`reponse.status_code`** : le code HTTP renvoyé (200 = OK, 404, 500…). Test `if reponse.status_code == 200`.
- **Site injoignable ≠ code** : un domaine inexistant/serveur éteint fait **planter** `requests.get` avec une exception → entourer d'un `try` / `except`.
- **`except requests.exceptions.RequestException:`** (nouvelle classe d'exception à attraper).

## Exercice fait — `python\site_online.py`
`input` d'une URL → `requests.get` dans un `try` → `status_code == 200` → « EN LIGNE » / sinon affiche le code → `except RequestException` → « injoignable ».
Tests : `google.com` → EN LIGNE (200) ✅ ; `sitequinexistepas12345.org` → injoignable ✅. Réussi.

## Difficultés / observations

- Tendance aux coquilles dans les identifiants/textes (`Reequest`, `INJOINGNABLE`) → point de relecture.
