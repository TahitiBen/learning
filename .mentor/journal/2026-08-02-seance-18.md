# Séance 18 — 2026-08-02 — STRUCTURER AVEC DES FONCTIONS (1)

## Objectif de la séance
Attaquer le point faible (architecture) : découper la logique en fonctions. 1re extraction.

## Révision éclair
- **Architecture avant/dans/après la boucle** : **juste** (input avant, traitement dans, total après). Bien assimilé — c'était le focus du bilan.
- Définir/appeler une fonction : partiel (a dit `def` + nom, « appeler le nom ») → complété : paramètres, **`return`**, et surtout les **parenthèses `()`** pour appeler + récupérer la valeur.

## Ce qui a été vu
- **Structurer = donner un nom à un bout de logique** via une fonction (1 fonction = 1 job). Le nom documente le code.
- Une fonction peut **renvoyer un bool** et être utilisée directement dans un `if` (`if est_sur_reseau(...)` se lit comme une phrase).
- Convention : `import` en haut, puis les fonctions, puis le code principal.

## Exercice fait — refactor `python\13_audit_reseau.py`
Extraction du test de filtre dans `def est_sur_reseau(ligne, reseau): return reseau + "." in ligne`, appelée dans la boucle via `if est_sur_reseau(ligne, reseau):`. **Marche à l'identique.** 1re fonction utilitaire réussie.

## Difficultés / observations
- **Première extraction de fonction réussie du 1er coup** — bon signe pour la structuration.
- Détails : a placé `def` avant `import` (convention : imports d'abord) → signalé ; espace avant la parenthèse dans le `def` (cosmétique, PEP 8).
- Rappel utile : le lien fonction→bool→`if` a renforcé sa question de la séance 17.
