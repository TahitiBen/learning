# Séance 31 — 2026-09-04 — Requêtes paramétrées & injection SQL

## Objectif
Sécuriser les requêtes avec des données utilisateur : injection SQL + placeholders `?`.

## Révision éclair
- `commit()` sur la **connexion** : juste.
- Cold GROUP BY : `SELECT reseau, COUNT(*) FROM machine GROUP BY reseau` → **structure enfin correcte** (colonne 2 fois) ! Juste `machine` → `machines`. **GROUP BY consolidé.** 🎉

## Ce qui a été vu
- **Injection SQL** : coller une donnée utilisateur avec `+` → son texte devient une partie de la commande. Ex. `' OR '1'='1` → renvoie TOUT (contourne le filtre).
- **Requêtes paramétrées** : `curseur.execute("... WHERE nom = ?", (nom,))` — le `?` = emplacement, valeur passée séparément dans un **tuple** `(nom,)` (virgule obligatoire), jamais interprétée comme du SQL.
- **Règle d'or** : donnée externe → toujours `?`, jamais `+`.

## Difficulté & déblocage (IMPORTANT pour la pédagogie)
- L'injection est restée **floue tant qu'on l'a expliquée avec des mots** (« je commence à comprendre mais c'est flou »).
- **Débloqué par l'EXPÉRIENCE** : `test_injection.py` version dangereuse → il a tapé `' OR '1'='1` et **vu TOUTES les machines s'afficher** ; puis version `?` → même attaque → **0 résultat**. Le contraste live a fait le déclic.
- → **Confirmation forte : pour un concept abstrait, faire une DÉMO/expérience à faire soi-même, pas d'explication verbale prolongée.**
