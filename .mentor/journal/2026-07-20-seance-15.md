## Objectif de la séance
Écrire un rapport dans un fichier de sortie (lire → parser → écrire).

## Révision éclair
- Mode `open` **`a`** : **ENFIN « append (ajouter) »** 🎉 — le mnémo « A comme Ajouter » a marché. À reconfirmer 1-2 fois puis espacer.
- `.split(":")` + index `[0]`/`[1]` (commence à 0) : juste.
- `.strip` vs `.strip()` : idée bonne ; précisé que `.strip` seul affiche la méthode (pas une « erreur »).

## Ce qui a été vu
- **Ouvrir deux fichiers à la fois** : `with open("hosts.txt","r") as entree, open("rapport.txt","w") as sortie:` (lire d'un côté, écrire de l'autre).
- **`f.write()` prend UNE chaîne** → la construire avec le `+` (concaténation) + `\n`.

## Exercice fait — `python\rapport.py`
Lit `hosts.txt`, parse (split), et écrit `rapport.txt` (une ligne « Machine : nom - IP : ip » par machine).
- v1 : sans `.strip()` → espace en trop + lignes vides (le `\n` de la ligne d'origine + celui ajouté). Cause bien rappelée (séance 12).
- v2 : `.strip()` sur l'IP → rapport propre. (N'a pas strip `[0]`, mais propre dans ses données.)

## Difficultés / observations
- Ouverture double + `f.write` + concaténation `+` : assemblés correctement.
- **Récurrent** : oublie le `.strip()` sur les lignes lues (le `\n`) → mais corrige vite, la cause est comprise.
- **Jalon** : 1er cycle complet **lire → parser → écrire** un rapport. Vrai mini-outil d'admin.

## Concepts — bilan
- Écrire un rapport (2 fichiers ouverts, `f.write`, concaténation `+`, `\n`) → **fragile→solide**. À reconfirmer.
- Module « fichiers/parsing » globalement bien avancé (read, ligne par ligne, filtrage `in`, `split`, write).
