# Séance 36 — 2026-09-04 — SQL : LEFT JOIN

## Objectif
Comprendre le `LEFT JOIN` (vs `INNER JOIN`).

## Révision éclair
- Cold JOIN : `SELECT reseau FROM machines JOIN reseau WHERE machines.reseau = reseau.reseau` → erreurs : table `reseau`→`reseaux`, **`WHERE`→`ON`** (condition de jointure), mauvaises colonnes. Recadré. → JOIN...**ON** à froid à driller.
- `DELETE` sans `*` : juste ✓.

## Ce qui a été vu
- **INNER JOIN** (le `JOIN` simple) = uniquement les lignes qui ont une correspondance **dans les 2 tables**.
- **LEFT JOIN** = **toutes** les lignes de la table de **gauche**, même sans correspondance à droite → colonnes de droite = `NULL`.

## Exercice fait — démo live
1. Ajout d'une machine `Orpheline` sur `172.16.0` (réseau **absent** de `reseaux`).
2. INNER JOIN → **6 lignes** (Orpheline absente).
3. LEFT JOIN → **7 lignes** (Orpheline présente, `localisation = NULL`).
Les 2 requêtes justes (avec `ON`), contraste clair.

## Difficultés / observations
- **LEFT JOIN compris** via le contraste live (6 vs 7 lignes). Cas d'usage saisi (repérer les données non documentées).
- Cold JOIN : a mis `WHERE` au lieu de `ON` → la condition de jointure = **`ON`**, à recroiser.

## Concepts — bilan
- `INNER JOIN` vs `LEFT JOIN` → **vu, compris**. À recroiser (avec le `ON`).
