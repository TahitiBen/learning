# Séance 39 — 2026-09-22 — Compléments Python : lire un champ précis d'une API JSON

## Objectif
Extraire **une valeur précise** d'un JSON d'API (`reponse.json()["clé"]`) sur un cas réel.

## Révision éclair
- **JOIN → `ON` : restitué à froid, sans indice, une 2e fois** → **ACQUIS**, drill retiré. 🎉
  `SELECT machines.nom, reseaux.localisation FROM machines LEFT JOIN reseaux ON machines.reseau = reseaux.reseau`
- **UPDATE à froid** (« changer l'IP de Serveur1 ») : « j'ai oublié » → reconstruit avec la trame en 4 morceaux (UPDATE/SET/WHERE). Deux corrections nécessaires : ciblait d'abord sur `ip` au lieu de `nom` ; puis coquille `'Server1'` vs `'Serveur1'`. Structure finalement juste. → **production SQL à froid encore fragile, à redriller.**

## Ce qui a été vu
- `.json()` renvoie un **dictionnaire** → on accède à une valeur par sa **clé entre crochets** : `donnees["public_repos"]`.
- Astuce : `print(donnees)` une fois pour repérer les clés disponibles, puis piocher.

## Exercice fait — `python\github_info.py`
API GitHub `https://api.github.com/users/TahitiBen` → `reponse.json()` → affiche `public_repos` (=1) et `created_at` (=2024-01-15…). Code propre, écrit **seul du 1er coup**, rien à corriger.

## Difficultés / observations
- Accès JSON par clé : **acquis rapidement**, aucun blocage.
- Point à surveiller : **production SQL à froid** (UPDATE) + **exactitude des noms/valeurs au caractère près** (coquilles récurrentes : `Server1`≠`Serveur1`).

## Concepts — bilan
- Accès à un champ JSON (`reponse.json()["clé"]`) → **vu, réussi seul**. À recroiser.
- JOIN → ON → **ACQUIS**.
